# ADR 0001. Перенос заготовки и поднятие стенда (этап 1)

- Статус: принято
- Дата: 2026-11-24

## Контекст

Этап 1 требует перенести заготовку контура из репозитория
hexlet-components/projects-llm-telecom-operator-agent и поднять стенд
(издатель JWT, read-MCP, REST-моки, база знаний, Postgres) с проверками
smoke-группы 0 без LLM. Разработка ведётся на Windows (Git Bash/PowerShell),
команды в спецификации даны для Linux. Автопроверка Хекслета вызывает
make-цели и работает на Ubuntu.

## Решение

1. Заготовка перенесена клонированием с удалением её .git и README.md;
   Makefile и готовый код (core/, services/, stand.py, web/, tests/smoke.py)
   не изменялись — цели Makefile должны совпадать с ожиданиями автопроверки.
2. Виртуальное окружение — Python 3.12 (`py -3.12 -m venv .venv`), активация
   `source .venv/Scripts/activate`.
3. LLM — локальная LM Studio (OpenAI-совместимый API,
   http://127.0.0.1:1234/v1, ключ-заглушка none). Модель эмбеддингов не
   используется: векторы базы знаний идут снапшотом kb/vectors.json.
4. Smoke-проверки на Windows запускаются как `python -m tests.smoke <G>`
   (флаг -m добавляет корень репозитория в sys.path), а не `make smoke`:
   рецепт цели использует POSIX-синтаксис `PYTHONPATH=.`, недоступный в
   cmd/PowerShell. Makefile ради этого не меняем — в CI он работает.
5. PDF-спецификации этапов хранятся локально в specification/ и не
   коммитятся (репозиторий публичный, материалы курса).

## Последствия

- Локальные команды отличаются от спецификации; рабочие варианты
  зафиксированы в AGENTS.md.
- Репозиторий совместим с автопроверкой: make-цели и код заготовки не тронуты.
- На следующих этапах smoke запускаем через `python -m tests.smoke <G>`,
  сервисы — через make-цели, как в спецификации.
- specification/ добавлена в .gitignore; AGENTS.md и docs/adr коммитятся.
