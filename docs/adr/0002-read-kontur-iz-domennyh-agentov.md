# 0002. Read-контур из доменных агентов с гейтом плана

## Статус

Принято (этап 2).

## Контекст

Ассистенту нужно отвечать на вопросы о данных абонента и о правилах
оператора, не давая модели свободного доступа ко всем инструментам сразу.
Один агент со всеми инструментами непредсказуем: малые локальные модели
щедро помечают шаги как действия и легко выходят за рамки задачи.
Требовалось: разделить обязанности, проверять план модели кодом до
исполнения и показывать пользователю ход работы.

## Решение

Ассистент собран из узких специалистов, которыми управляет код:

- Планировщик (`app/planner.py`) — агент со структурированным выходом
  `Plan` (нестрогая схема `AgentOutputSchema(strict_json_schema=False)` —
  строгий JSON-режим валит малые модели). Схемы принимают алиасы
  `agentName`/`job`, потому что модели отвечают своим диалектом имён.
- Гейт `gate()` фильтрует план до исполнения: шаги неизвестных агентов
  отбрасываются, у агентов чтения пометка `action` снимается — ошибку
  «action=true на всё подряд» исправляет код, а не промпт.
- Доменные агенты (`app/workers.py`) собираются из каталога `CATALOG`:
  у каждого свой allowlist инструментов из MCP-пула сессии
  (`app/wrap.py` оборачивает их в FunctionTool с Bearer-токеном).
  Агент данных не может искать в базе знаний, агент базы знаний не
  может тронуть тариф.
- Редактор (`app/editor.py`) — единственный агент, чей текст видит
  пользователь; отвечает строго по докладам и называет источники kb.
- Оркестратор (`app/orchestrator.py`) связывает части: план → гейт
  (отброшенное — в трейс сессии) → шаги отдельными `Runner.run` →
  редактор. Каждый этап уходит во фронтенд событием SSE (`plan`,
  `reply`); `sources` собираются кодом из tool-результатов `search_kb`,
  а не из текста модели.
- HTTP-граница (`app/main.py`): `POST /api/session`, `POST /api/chat`
  (SSE через `asyncio.Queue` + `StreamingResponse`, сбой хода —
  событие `error`, не падение потока), `GET /api/health`.

## Последствия

- Плюсы: план модели никогда не исполняется без фильтра кода; allowlist
  инструментов задаётся при сборке агента; источники в ответе
  гарантированы кодом; трейс сессии показывает отброшенные шаги.
- Минусы: больше LLM-вызовов на ход (планировщик + агенты + редактор) —
  латентность растёт линейно по шагам плана.
- Ограничение этапа: шаги действий (`tariff`, `tickets`) гейт пропускает,
  но исполнителей у них нет — они появятся вместе с action-MCP на этапе 3.
